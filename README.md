## 一、 项目背景与业务痛点

在石化工程建设、核能装备制造、压力容器制造及特种流体管线物资采购中，供应商每批物料均须随货交付原厂产品质量证明书（MTC / Mill Test Certificate）。这类工程单据呈现出高度专业性与复杂性：

- **格式异构与多源异相**：各钢厂、管件制造厂排版差异巨大，单据涵盖化学成分分析、常温/高温拉伸试验、多测点硬度、晶间腐蚀倾向、无损探伤（超声 UT / 涡流 ET / 射线 RT）、水压/气压试验、阶梯公差几何尺寸及各类工程特约附加要求；
- **多层级执行标准与交叉约束**：同一批物资通常同时受控于**国家标准**（如《GB/T 13296-2023》）、**行业标准**（如《NB/T 47019.5-2021》）及**工程订货技术协议**。各标准间存在前置适用口径、阶梯公差表、替代试验条款（如涡流替代水压）以及新旧版本升级导致的指标“剪刀差”；
- **传统质检困境**：人工逐行核对不仅耗时费力、极易因视觉疲劳产生漏检漏放；而通用的通用 OCR 或纯向量 RAG 系统对微小数值超标不敏感（例如碳含量超标 $0.005\%$ 极易被误判为语义高度相似），且难以承载前置规格路由、跨字段动态公式判定与质量一票否决机制。

**准衡 NormScale** 旨在构建一套**工业级、确定性优先、可解释、零丢失且支持人机协同（HITL）**的特种物资合规检验与智能比对系统。

## 二、 系统总体设计架构

系统遵循“**确定性纯代码计算为主，大模型多模态语义消歧为辅**”的双轨制原则构建，整体分层架构如下：

```
┌────────────────────────────────────────────────────────────────────────┐
│                   表现层 (Presentation & HITL Interaction)              │
│   受控垂直滑动工作台 │ 国家标准切片浏览器 │ 历史检验台账 │ 运维日志监控控制台 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│                  流水线编排与数据生命周期管理 (Pipeline & State)           │
│   预处理切图与文本分离 │ 三级缓存 (L1/L2/L3) │ 全渠道双向投影门禁 │ 零丢弃数据漏斗 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│                    四维分层核验引擎 (Four-Tier Evaluation)              │
│   Tier 1 规则快筛 ──► Tier 2 AI消歧 ──► Tier 3 HITL协同 ──► Tier 4 经验反哺 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│                  离线标准知识仓储与领域内核 (Core & Store)               │
│   通用规格切片 (IRuleStore) │ GB/T 8170 数值修约 │ 阶梯公差表 │ 双标准剪刀差比对 │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. 双轨制合规核验架构 (Dual-Track Architecture)
- **理化指标确定性硬核验**：化学成分、抗拉强度、屈服强度、断后伸长率、多标度硬度、阶梯几何尺寸公差等定量指标，统一由 TypeScript 纯函数直接基于结构化标准规则进行区间比对与代数运算。严格引入 **GB/T 8170** 进舍修约标准（四舍六入五成双），微秒级执行完成，**实现理化检验核心判定零幻觉**；
- **非标定性条款语义意图对齐**：针对晶间腐蚀检验方法（如敏化制样要求）、表面质量描述、无损探伤结论等长尾非标条款，借助大模型语义理解完成标准条文对齐与语义判别。

### 2. 四维分层核验流转体系 (Four-Tier Pipeline)
- **Tier 1 (Fast-Path 规则快筛)**：标准字段直通本地规则库，毫秒级快速完成 90% 以上常规检验项的比对；
- **Tier 2 (大模型语义消歧)**：当遭遇长尾别名、特殊缩写或非标表述时，触发大模型进行语义归一化（如将 `表面粗糙度 0.33μm` 映射至标准条文 `surface_roughness` 并核算合规性）；
- **Tier 3 (行内 HITL 人机协同)**：当识别到特种非标指标（置信度不足）或严重质量偏离报警时，流水线适时挂起并弹出抽屉，由质检工程师确认协议放行或执行缺项否决；
- **Tier 4 (动态别名自学习反哺闭环)**：经质检工程师人工确认的属性映射关系自动沉淀至动态别名知识库。当系统后续再次处理相同供应商的单据时，自动直通 Tier 1 Fast-Path，实现系统越用越准、越用越快。

### 3. 多标准智能组合与“剪刀差”归因 (Multi-Standard Composer)
- 支持同时挂接国家标准、行业标准与工程技术协议；
- 引擎自动组合求取多标准交集，推导最严考核基准；
- 自动识别由于标准版本演进或双标准控制产生的**指标剪刀差**（例如基准国标判定合格，但加严行标判定超标），并在全景矩阵中精准标记与归因。

### 4. 工业级三级缓存体系 (L1 / L2 / L3 Caching)
- **L1 (解析级缓存)**：当输入文档 MD5 与当前系统 Schema / Prompt 版本完全匹配时，直接秒级还原完整结构化结果（0 Token 消耗）；
- **L2 (预处理级缓存)**：切图 PNG 与提取文本层持久化保存，重复解析或跨版本更新时跳过渲染切图，直接调用大模型；
- **L3 (原件存储)**：原件二进制持久化留档，作为审计比对与原真追溯的法定物理依据。

### 5. 全局门禁心智模型与数据漏斗“零丢失”契约
- **领域模型作为单一真实源 (SSOT)**：全局流转判定严格依赖 `session.documents` 领域实体状态，解耦局部 UI 瞬态视窗；无论是全新上传、缓存命中还是历史台账回溯，均实现双向投影；
- **零丢弃数据平衡恒等式**：
  $$\text{工作台步骤 3 全部比对项} = \text{质保书实测对齐项} + \text{标准缺漏检项 (MISSING)} + \text{工程追溯参考项}$$
  系统建立自动化断言矩阵，严禁任何原始凭单中提取的实测数据在流转、消歧或比对环节被意外丢弃。

## 四、 核心功能与工作流

系统提供清晰的四步骤垂直流转质检闭环：

### 1. 步骤 1：文档上传与切图预处理
- 支持批量拖拽上传工业 PDF 文档及主流图片格式（`PNG / JPEG / JPG / BMP`）；
- 自动完成格式合法性准入检查，生成文件 MD5 唯一指纹；
- 客户端秒级提取矢量文本层（分离保存为 `text.txt`），并渲染为 2.0x Retina 高清逐页切图；
- 具备历史缓存自动探测能力，支持从下方缓存卡片一键秒级载入已预处理或已解析的文档。

### 2. 步骤 2：多模态智能解析与双屏核对
- 调用多模态大模型进行多炉批号、全理化指标的结构化抽取；
- 提供流式解析状态监控，实时统计字符吞吐、Token 开销与模型首字响应时间（TTFT）；
- **双屏联动核对**：左屏展示原始单据高清晰度切图（支持放大镜微检、旋转与 BBox 视觉坐标对齐反显），右屏卡片式分组呈现解析数据并支持实时修正。

### 3. 步骤 3：全景比对矩阵与多标准判定
- 挂载对应国家标准、行业标准及工程订货技术协议；
- 自动生成多维度合规比对矩阵，展示条款指标要求、实测值、代数偏差量与判定结果（PASS / FAIL / 缺项漏检 MISSING / 剪刀差报警）；
- 行内无缝集成 HITL 人机协同抽屉，质检工程师可针对争议项一键录入特约放行说明或确认缺项否决；
- 底部常驻控制栏集成平滑“返回顶部”快捷按钮，方便长矩阵表格高效检视。

### 4. 步骤 4：不可篡改归档与历史台账存证
- 一键将当前检验结果持久化归档至服务端，生成具备时戳签名的审计会话 JSON；
- 提供专用的“**历史检验台账**”视图，按时间倒序快速检索、复核历史质检记录，并支持将历史台账数据完整反向载入回工作台再次比对。

### 5. 辅助视图能力
- **国家标准切片浏览器 (StandardExplorer)**：直观检索与浏览离线标准库（如 GB/T 13296、NB/T 47019.5 等），查看化学成分表、力学性能、工艺试验要求与阶梯公差表；
- **系统运维控制台 (AdminConsole)**：实时监控系统运行日志（支持按级别/模块过滤），动态调整大模型推理端点、配置参数与日志输出级别。

## 五、 快速上手 (Quick Start)

### 1. 环境准备
确保本机已安装 Node.js 22 LTS 以及 pnpm：
```bash
node -v   # 应输出 v22.x.x
pnpm -v   # 应输出 9.x.x 或更新版本
```

### 2. 获取代码与安装依赖
```bash
git clone <repository_url> NormScale
cd NormScale
pnpm install
```

### 3. 配置环境变量
复制根目录环境变量模板：
```bash
cp .env.example .env
```
根据实际环境编辑 `.env` 文件中的必要参数：
```env
# ── 大模型 API 密钥配置 ──
KIMI_API_KEY=your_api_key_here

# ── 测试用例与场景矩阵受控开关 ──
# true:  (默认) 启用四维分层场景测试矩阵，在步骤 1 欢迎区展示并允许一键装载测试数据
# false: 彻底卸载测试用例矩阵，API 与前端组件均不加载测试数据，实现生产零残留
NEXT_PUBLIC_ENABLE_TEST_FIXTURES=true

# ── LangSmith 追踪与监控 (可选) ──
LANGSMITH_TRACING=false
LANGSMITH_ENDPOINT=https://api.smith.langchain.com
LANGSMITH_API_KEY=your_langsmith_api_key_here
LANGSMITH_PROJECT=NormScale
```

### 4. 启动本地开发服务
```bash
pnpm dev
```
启动成功后，使用现代浏览器访问：
👉 **http://localhost:3000** 即可进入系统主控制台。

## 八、 标准切片扩展指南

系统采用接口隔离的 `IRuleStore` 仓储架构。如需录入新的国家、行业标准或企业技术协议，仅需在 `data/standards/` 下按统一格式新增规格切片文件：

```
data/standards/<标准代号>/
├── meta.json                  # 标准元数据 (代号、名称、版本、适用材料范围)
└── slices/                    # 具体规格切片
    ├── <牌号1>.json            # 该牌号对应的化学、力学、工艺试验规则
    └── <牌号2>.json
```

新增切片后，执行自检命令验证数据合法性：
```bash
pnpm standard:validate
```
切片通过校验后，前端 `StandardExplorer` 与比对引擎即可自动感知并加载该标准，无需改动任何核心引擎代码。
