# NormScale 物资验收决策看板 UI/UX 设计方案与高保真原型

本文档详尽展示 **Phase 6 前端决策看板** 的视觉风格、排版层级约束、交互动效设计以及 3 大典型业务场景的高保真原型规范。

---

## 1. 视觉风格与设计原则 (Design System & Principles)

NormScale 前端严格遵循**现代极简、注重排版层级、低饱和度工业质感（Modern Minimalist & Industrial Precision）**设计原则：

* **配色与低饱和度质感 (Low-Saturation Palette)**：
  - 深色基底：沉稳低反光深灰（`bg-slate-950` / `bg-zinc-900`）配合极细边框（`border-slate-800` / `border-zinc-800`）；
  - 文字层级：主标题与核心数据采用 `text-slate-100`，次要属性采用 `text-slate-400`，辅助说明采用 `text-slate-500`；
  - 状态指示色：采用低饱和度专业语义色彩，告别刺眼高光：
    * **合规通过 (PASS)**：低饱和度翡翠绿（`text-emerald-400` / `bg-emerald-950/40` / `border-emerald-800/60`）；
    * **不合格 (FAIL)**：低饱和度柔和红（`text-rose-400` / `bg-rose-950/40` / `border-rose-800/60`）；
    * **漏检 (MISSING) / 人机协同 (HITL)**：低饱和度琥珀金（`text-amber-400` / `bg-amber-950/40` / `border-amber-800/60`）；
    * **单位换算 / 消歧说明**：沉稳青蓝（`text-cyan-400` / `bg-cyan-950/30` / `border-cyan-800/50`）。
* **无 Emoji 纯矢量图标体系 (Strictly Lucide Icons)**：
  - **严禁直接渲染 Emoji 字符**；
  - 全部状态、操作、导航与指示一律使用 `lucide-react` 纯矢量图标（如 `<ShieldCheck />`, `<CheckCircle2 />`, `<AlertTriangle />`, `<XCircle />`, `<RotateCcw />`, `<Download />`, `<FileText />` 等）。
* **组件化标准**：
  - 禁止裸写自定义原生 CSS，全部样式统一采用 Tailwind CSS 工具类与 `shadcn/ui` 原子化组件模式。

## 2. 字号与排版硬性约束 (Typography & Layout Rules)

* **【字号基准】**：
  - 默认正文、数据表格内容、表单 Label、按钮文本一律使用 `text-sm` (14px) 或 `text-base` (16px)；
  - 行高严格配合 `leading-normal` 或 `leading-relaxed`，保障工业报表审阅的舒适度。
* **【严禁滥用与降级】**：
  - 严禁在按钮（Button）、输入框（Input）、列表项（List Item）和卡片正文中使用 `text-xs`；
  - `text-xs` (12px) **仅限**用于时间戳（如 "2026-08-23 09:12"）、微型数字角标和次要耗时标注（如 "3.6ms"）。
* **【层级区分】**：
  - 依靠字重（`font-medium` / `font-semibold` / `font-bold`）与对比度（`text-slate-100` vs `text-slate-400`）构建清晰的信息架构，杜绝通过无底线缩小字号来做信息排版。
* **【等宽数值对齐】**：
  - 所有检测数值、百分比、上下限区间统一应用 `font-mono tabular-nums`，确保化学元素与力学指标多位小数纵向精确对齐。

## 3. 交互与动效规范 (Motion & Micro-interactions)

* **列表渲染与流式动画**：
  - 引入 `framer-motion`，所有判定项列表、状态切换与时间轴卡片采用平滑淡入（`fade-in`）与尺寸自适应（`layout` / `AnimatePresence`）；
* **触觉与点击回弹**：
  - 所有按钮与交互卡片具备清晰的 Hover 亮度提升与点击回弹动效（`transition-all duration-150 active:scale-95`）。

## 5. 典型业务场景交互效果

### 场景 1：标准质保书全自动核验 (Happy Path)
* **左列**：清晰排版单据信息与 15 项原始检验数据；
* **右列**：
  - 顶部低饱和度翡翠绿 `<CheckCircle2 />`「合格 (PASS)」横幅；
  - 判定明细表格使用 `text-sm leading-normal` 清晰排版，鼠标悬浮时展示标准修约或公式说明；
  - 底部审计时间轴通过 `framer-motion` 平滑展开。

---

### 场景 2：工程制单位换算与漏检一票否决 (Fail & Missing)
* **左列**：力学性能显示原始工程单位 `58.5 kgf/mm²`；
* **右列**：
  - 顶部低饱和度柔和红 `<XCircle />`「不合格 (FAIL)」横幅；
  - 弹出低饱和度琥珀金 `<AlertTriangle />`「发现 3 项国家标准强制出厂检验项缺失」警示栏：
    * 压扁试验（Flattening Test）未报送
    * 扩口试验（Flaring Test）未报送
    * 晶间腐蚀试验（Intergranular Corrosion）未报送
  - 判定表格中，抗拉强度显示换算标记 `573.68 MPa (由 58.5 kgf/mm² 换算)`，显示为绿色 PASS 徽章；
  - 漏检项目显示为醒目琥珀色 `MISSING` 标签。

---

### 场景 3：人机协同干预抽屉 (HITL Drawer Interaction)
* **触发条件**：遇到未知牌号或低置信度数据时，工作流触发 `interrupt()` 挂起；
* **右侧平滑滑出抽屉 (基于 framer-motion AnimatePresence 抽屉组件)**：

* **质检员点击「提交修正并恢复核验」后**：
  - 前端调用 `POST /api/audit/resume/[taskId]`；

  - 右侧判定矩阵即时刷新为合格结果，时间轴追加一条 `[人工介入生效] 质检员 QA-8821 修正牌号为 06Cr19Ni10` 的审计记录。
