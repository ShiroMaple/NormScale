# NormScale Alpha 1.0.0 阶段性开发总结与演化全景

## 一、 里程碑定位与阶段定义

经过持续的敏捷攻坚与闭环验证，**准衡 NormScale** 正式达成 **Alpha 1.0.0** 阶段性里程碑。

- **核心定位**：本版本定义为**工业级特种物资质量证明书 (MTC) 自动化检验、语义消歧与多标准比对引擎的首发可用版本（Alpha 1.0.0）**；
- **演化战略**：确立“**边试用、边反馈、边开发（Trial-Feedback Loop）**”的飞轮模式。在真实生产与业务一线试用中，持续接触更广泛的质保书版式、小众执行标准、工程边界问题与前期未预料的极端异常，驱动 LLM 提示词工程微调、规则库扩充与系统鲁棒性升级。

## 二、 已交付的核心系统架构与工程资产

系统围绕“**确定性纯代码计算为主，大模型多模态语义消歧为辅**”的核心技术路线，构筑了高可信、可解释、高韧性的工程基石：

```
┌────────────────────────────────────────────────────────────────────────┐
│                   表现层 (Presentation & HITL Interaction)              │
│   受控垂直滑动工作台 │ 国家标准切片浏览器 │ 历史检验台账 │ 运维日志监控控制台 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│                  流水线编排与数据生命周期管理 (Pipeline & State)           │
│   预处理切图与文本分离 │ 三级缓存 (L1/L2/L3) │ 全渠道双向投影门禁 │ 零丢弃数据漏斗 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│                    四维分层核验引擎 (Four-Tier Evaluation)              │
│   Tier 1 规则快筛 ──► Tier 2 AI消歧 ──► Tier 3 HITL协同 ──► Tier 4 经验反哺 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│                  离线标准知识仓储与领域内核 (Core & Store)               │
│   通用规格切片 (IRuleStore) │ GB/T 8170 数值修约 │ 阶梯公差表 │ 双标准剪刀差比对 │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. 双轨制合规核验引擎 (Dual-Track Engine)
- **理化指标确定性硬核验**：化学成分分析、常温/高温拉伸强度、屈服强度、伸长率、硬度标度换算、口径/壁厚阶梯公差等定量项目，统一通过 TypeScript 纯函数直接比对结构化标准规则库，严格执行 **GB/T 8170** 进舍规则（四舍六入五成双），微秒级完成运算，**实现理化检验核心判定零幻觉**；
- **定性长尾条款语义意图对齐**：针对晶间腐蚀试验方法（如敏化处理方式）、无损探伤规程、表面光洁度描述等非标定性条款，通过大模型进行标准条文匹配与语义意图消歧。

### 2. 四维分层核验流转体系 (Four-Tier Pipeline)
- **Tier 1 (Fast-Path 规则快筛)**：90% 以上的标准检验项毫秒级直通本地规则库判定；
- **Tier 2 (大模型意图消歧)**：针对特殊别名或长尾表述（如 `表面粗糙度 0.33μm` 对齐至 `surface_roughness`），触发大模型语义归一；
- **Tier 3 (行内 HITL 人机协同)**：当识别到非标未收录指标（置信度不足）或严重质量偏离报警时，流水线适时挂起并弹出抽屉，由质检工程师确认协议特约放行或确认缺项否决；
- **Tier 4 (动态别名自学习反哺闭环)**：质检工程师人工确认的属性映射关系自动沉淀至动态别名库，相同供应商后续单据直通 Tier 1 Fast-Path。

### 3. 多标准智能组合与“剪刀差”归因 (Multi-Standard Composer)
- 纯函数切片合成器 `composeMultiStandardSlices()` 泛化支持 $N \ge 2$ 份标准规则叠加，实现“检验项目取全量并集、共有指标取严苛交集（包络线原则 / Strict Superiority）”；
- 自动识别由于标准版本升级产生的**指标剪刀差**，并在全景矩阵中高亮警示与精准归因；
- 实现放行仲裁矩阵 `resolveFinalDisposition`，系统客观计算判定与质检员人工签认双轨并行流转，杜绝数据被静默覆盖。

### 4. 工业级三级缓存体系 (L1 / L2 / L3 Caching)
- **L1 (解析级缓存)**：文档 MD5 与当前系统 Schema / Prompt 版本匹配时直接秒级还原（0 Token 开销）；
- **L2 (预处理级缓存)**：切图 PNG 与提取文本层持久化，重复解析或模型重试时跳过切图直接调用模型；
- **L3 (原件存储)**：原件二进制持久化留档，作为不可篡改的法定物理证据。

### 5. 全局门禁心智模型与数据漏斗“零丢失”契约
- 全局判定统一以领域实体模型 `session.documents` 为单一真实源（SSOT），彻底解耦步骤 1 的局部 UI 瞬态视窗，支持全新上传、历史缓存恢复与检验台账载入的全渠道双向投影；
- 建立数据漏斗平衡恒等式自动化断言：
  $$\text{全部比对项} = \text{质保书实测对齐项} + \text{标准缺漏检项 (MISSING)} + \text{工程追溯参考项}$$
  严禁任何质保书实测内容在流转过程中被静默丢弃。

### 6. 质量工程与持续交付闭环
- **自动化测试保障**：建立包含 54 个自动化测试套件、265 项单元与端到端场景流转测试，本地与 Linux 纯净环境 100% 绿灯通过；
- **TypeScript 严格类型安全**：全项目开启严格模式，静态检查零报错 (`tsc --noEmit`)；
- **生产级 CI/CD 自动化**：建立 GitHub Actions (GitHub Hosted) 云端流水线，构建包排除缓存瘦身至 6.6MB，通过专用 SSH Key 自动化同步发布至目标服务器并由 PM2 守护集群运行于 4006 端口，配置 Nginx 泛域名 SSL 反代及持久化 `.env` 隔离。

## 三、 关键架构决策与踩坑经验 (Decisions & Lessons)

### 1. 坚决否定纯向量 RAG 用于数值核验
- **背景**：项目初期曾探讨是否可通过向量化切块比对国标。
- **结论**：Embedding 模型对微小数值差异不敏感（如碳含量超差 $0.005\%$ 易被误判为极其相似），且分块切片会割裂国标表格中的前置尺寸条件（如壁厚 $\ge 1.7\text{mm}$ 才做硬度）。
- **决策**：理化数值坚决走纯代码 TypeScript 确定性运算，零幻觉、零延迟。

### 2. 大模型提取长尾兜底与 Zero-Drop Policy
- **踩坑**：大模型在多页、密集表格抽取时偶发性出现“提前闭合 JSON”导致表格末尾的“外观质量”或附加试验被截断漏提。
- **治理**：在提示词中确立「全量无损提取与长尾兜底准则 (Zero-Drop Policy)」，要求模型行级扫描至物理末尾，未预设键统一存入 `additional_tests` 数组，从源头杜绝漏损。

### 3. CI 纯净环境测试固件解耦
- **踩坑**：部分场景测试曾直接读取本地开发生成的 `.cache/parses/*.json`，因 `.cache/` 被 gitignore，导致在 GitHub Actions 纯净 runner 上执行单测失败。
- **治理**：将测试场景种子固化至 `tests/fixtures/scenarios/seeds/` 并剥离大型 Base64 图片，确保在任意离线、只读或全新检出的 CI 环境中测试均能秒级确定性通过。

### 4. 生产发布包排除构建缓存
- **踩坑**：首次发布包直接打包 `.next`，体积高达 170MB，网络传输缓慢。
- **治理**：排查发现 `.next/cache/webpack` 占用了 96% 体积，运行时并不需要；打包时通过 `--exclude=.next/cache` 瘦身至 6.6MB，传输与解包速度提升十倍以上。

## 四、 当前能力边界与已知局限 (Current Boundaries & Limitations)

在 Alpha 1.0.0 版本中，已明确以下边界与待拓展方向：

1. **品类与标准覆盖面**：
   - 当前主要针对特种不锈钢换热管及承压设备用管（如《GB/T 13296-2023》、《NB/T 47019.5-2021》，涵盖 S30408/06Cr18Ni11Ti/S32168 等典型材料）；
   - 碳钢结构管（GB/T 8163）、高压锅炉管（GB/T 5310）、锻件板材以及外标（ASME SA-213, EN 10216）尚待后续批次扩充入库。
2. **纯图片扫描件的字符坐标提取**：
   - 矢量 PDF 可由客户端 PDF.js 秒级提取矢量 Token 坐标；
   - 纯图片扫描件（无文本层）目前依赖全图视觉定位，字符级微米级物理 BBox 后续需引入轻量 OCR (如 PaddleOCR / ONNX Runtime) 进行补充。
3. **复杂跨页大表格与非标手写体**：
   - 极端倾斜、折痕遮挡、手写加签或长达数十页的复杂异构质保书，仍存在抽取不全或个别字段置信度偏低的可能，此时依赖 Tier 3 HITL 抽屉由工程师人工核对放行。

## 五、 Alpha 1.0.0 后的演进路线（边试用、边反馈、边开发）

后续开发将以“**真实场景试用驱动开发**”为主线：

```
      ┌───────────────────────────────────────────────┐
      │          一线质检试用 (Trial in Action)         │
      │   真实批次 MTC 上传 ──► 多标准自动比对 ──► 人工复核 │
      └───────────────────────┬───────────────────────┘
                              │
                              ▼
      ┌───────────────────────────────────────────────┐
      │          样本反馈飞轮 (Feedback Flywheel)       │
      │   收集边缘案例 (Edge Cases) ──► 归档至典型样本库 │
      └───────────────────────┬───────────────────────┘
                              │
                              ▼
      ┌───────────────────────────────────────────────┐
      │          持续敏捷演进 (Continuous Evolution)   │
      │  优化 Prompt / 扩充标准切片 / 强化动态别名自学习 │
      └───────────────────────────────────────────────┘
```

1. **建立样本反馈收集流**：
   - 在使用中遇到格式异常、提取缺失或比对争议时，一键归档该 MTC 切片与会话 JSON，作为系统优化的高价值样本；
2. **大模型提示词工程持续迭代**：
   - 结合新样本特征，迭代优化提示词结构、格式约束与思考强度（Thinking Effort），持续提升首次全项提取准确率；
3. **基于 IRuleStore 平滑扩充标准知识库**：
   - 零改动核心引擎，按规范向 `data/standards/` 增补新标准规格切片；
4. **质检经验反哺加速**：
   - 充分利用已落地的 Tier 4 动态别名自学习能力，使系统在日常试用中“越用越聪明、越用越快”。
